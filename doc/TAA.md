# TAA 学习路线

| 课 | 主题 | 学完能看到什么 |
|---|---|---|
| **第 1 课** | 拆出 HDR 缓冲，加入随时间变化的抖动，做最简单的累积 | 相机静止时，噪点慢慢收敛干净 |
| 第 2 课 | 重投影：深度、上一帧矩阵、历史缓冲 | 相机移动时也能累积 |
| 第 3 课 | 历史拒绝：邻域方差裁剪（YCoCg） | ghosting 消失 |
| 第 4 课 | 用流体速度场算运动矢量 | 烟在流动时依然稳定 |
| 第 5 课 | 收回收益：放大步长或半分辨率 TAAU | 同样画质下更快 |

每课结构相同：原理 → 任务 → 检查点 → 思考题。今天讲第 1 课。

# 第 1 课：给时间维度"喂"新信息

## 原理

**TAA 的本质是把多帧的样本平均起来。** 当前的 ray march 每个像素每帧只取一组样本：步进起点由 [cuda_renderer.cu:405](src/cuda/cuda_renderer.cu#L405) 的 IGN 抖动决定，而这个值只依赖 `(x, y)`。

**思考一下：** 如果每帧的抖动都一样，把 100 帧平均起来，得到的是什么？

答案是和单帧完全一样。重复的样本没有带来任何新信息。所以第一件事是让抖动随帧号变化：

```
offset = fract(IGN(x, y) + frameIndex * 0.6180339887)
```

这里用黄金比例，是因为它生成的是一维低差异序列：任意连续 N 帧的偏移都分布得比较均匀，比随机数收敛得快。

**第二件事：平均要在 HDR 线性空间里做。** 现在 [cuda_renderer.cu:506](src/cuda/cuda_renderer.cu#L506) 在 kernel 里先 tonemap，再量化成 uint8。tonemap 是非线性的，而且是压缩性的，所以"先平均再 tonemap"和"先 tonemap 再平均"结果不同。只有前者在物理上正确。uint8 还会把精度丢掉，累积时误差会叠加。

因此管线要拆成两步：

```
renderKernel  ──► float4 HDR 缓冲（线性 radiance）
                        │
resolveKernel ──► tonemap + dither ──► uint8 像素
```

第 2、3 课的 TAA 逻辑就插在这两步之间。

## 任务

**1.1 加一块 HDR 缓冲**
- 参考 [cuda_renderer.h:66](src/cuda/cuda_renderer.h#L66) 的 `devicePixels_`，加一个 `DeviceBuffer<float4>`。
- 在 [cuda_renderer.cu:627](src/cuda/cuda_renderer.cu#L627) 附近，也就是 `setResolution` 里，按分辨率分配它。

**1.2 拆分 kernel**
- `renderKernel` 只把 `radiance` 写进 HDR 缓冲。unlit 分支本来就是最终颜色，原样写入即可。
- 新写一个 `resolveKernel`：读 HDR，在 `params.lit` 时做 `toneMap`，然后加 dither，写入 uint8。
- 在 `render()` 里依次发射这两个 kernel。可以给第二个也套一个 `GpuScope`，profiler 就能单独显示它的耗时。

> **检查点 A：** 按 `Space` 暂停模拟，按 `P` 截图，改代码前后各截一张。两张图应该逐像素一致（最多差 1/255）。如果不一致，说明拆分时漏了什么。这是重构，不应该改变画面。

**1.3 让抖动随时间变化**
- 给 kernel 传一个 `frameIndex`。放进 `RenderParams`，或者作为单独的参数都可以，想想哪种更合理。
- 只改**沿视线的起点抖动**，最后的输出 dither 先不动。

> **检查点 B：** 暂停模拟，相机不动。你应该看到画面开始闪烁，噪声在动。这是预期结果：噪声从空间上固定的图案变成了随时间变化的噪声，正是 TAA 需要的原料。
>
> **小实验：** 把 [cuda_renderer.cu:429](src/cuda/cuda_renderer.cu#L429) 的步长从 `0.5` 临时改成 `2.0`。对比改 1.3 之前和之后：之前是固定的条纹或块状图案，之后是闪烁的噪声。

**1.4 最朴素的累积（第 1 课的高潮）**
- 再加一块 `float4` 历史缓冲。在 `resolveKernel` 里，tonemap 之前先混合：
  ```
  history = lerp(history, current, α)
  ```
- 先固定 `α = 0.05`，然后试试 `α = 1 / (n + 1)`（n 是累积的帧数）。两者有什么区别？
- 相机一动、或者模拟没暂停时，先简单粗暴地重置：令 `n = 0`。想想这个信号从哪里拿：相机状态在 `camera_` 里，暂停状态在 `main.cpp` 的 `PAUSE`。

> **检查点 C：** 暂停模拟，步长保持 `2.0`，相机不动。几秒后画面应该收敛到接近步长 `0.5` 时的质量，甚至更好。然后把模拟恢复（按 `Space`，并且不重置 n），观察烟后面拖出的残影。这就是 **ghosting**，也是第 2、3 课要解决的问题。

## 思考题（下次我们先讨论这几个）

1. 输出 dither 为什么必须留在 tonemap 和量化**之后**，而且**不该**参与累积？
2. `α = 0.05` 的指数滑动平均，大约等效于平均了多少帧？`1/(n+1)` 收敛到的又是什么？
3. 第 1.4 步里，相机一动就重置历史。真正的 TAA 用什么手段代替"重置"？提示：想一想上一帧这个像素看到的东西，现在在屏幕的什么位置。
